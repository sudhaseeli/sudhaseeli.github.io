KubeSleuth · Agentic SRE for Kubernetes

An AI agent that investigates Kubernetes incidents the way an on-call engineer would. When an alert fires, it works out the root cause on its own and proposes one fix, and nothing changes until a human approves it. It finishes with a structured incident report.

  • Investigate: reads pods, crash logs, events, rollout history and Prometheus metrics through read-only tools, which are also served over MCP.
  • Fix safely: proposes one change from an allowlist (roll back, raise a memory limit, cordon a node…) behind a human approval gate. Its RBAC role can’t read Secrets.
  • Measured: a built-in eval of six realistic incidents (OOMKilled, crash loops, bad image tags, bad rollouts, disk pressure, broken probes). The offline playbook diagnoses and resolves 6/6, and the same eval scores the Claude brain.

your cursor is a new incident · nearest matches light up

AI Incident Intelligence & Root-Cause Copilot

When a production system breaks, an on-call engineer has to find out why, usually by reading thousands of log lines under time pressure. This copilot does that first pass for them. It reads the alert and logs of a new incident, finds the most similar incidents from the past, and suggests the likely root cause and the fix that worked before, so engineers spend less time digging through logs.

Incidents it diagnoses, with example fixes

OOMKilled
a pod ran out of memory → raise the memory limit or fix the leak
CrashLoopBackOff
a service keeps restarting → roll back the bad config or deploy
5xx error spike
users get server errors → find the slow upstream, scale replicas
DiskPressure
a node’s disk is full → clean up logs, add a retention policy
Certificate expiry
TLS cert expired → renew it with cert-manager
  • Search: compares the new incident against 10,000+ log events and 500+ simulated past incidents, using vector search in PostgreSQL with pgvector.
  • Explain: a RAG pipeline uses the closest matches to write a root-cause summary with a confidence score and recommended next steps.
  • Run: FastAPI backend, React dashboard and Redis caching, deployed on AWS EKS with Terraform.
